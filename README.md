# 转化数据分析小程序 V1.9

这是从原 ChatGPT 开发文件迁移到 VS Code 的本地开发工作区。当前迁移保持 V1.9 的业务逻辑、样例数据和界面行为不变，可直接运行并继续开发。

## 快速启动

在 VS Code 终端执行：

```powershell
npm run dev
```

浏览器打开 `http://127.0.0.1:4173`。修改 `index.html` 后刷新页面即可看到结果。

也可以打开 VS Code 命令面板，运行 `Tasks: Run Task`，然后选择“启动 V1.9 本地预览”。

迁移后的项目不需要安装 npm 依赖。Excel 导出仍沿用原版的在线 XLSX 组件，因此该功能需要联网加载 CDN。

## 项目检查

```powershell
npm run check
```

检查内容包括：内嵌样例数据是否可解析、CAM 是否为空或重复、字段数量以及内联 JavaScript 语法。

## 当前代码层次

`index.html` 仍保留原来的单文件结构，主要由以下部分组成：

1. 基础样式与 V1.4 至 V1.9 的增量样式。
2. 数据看板、数据分析、转化用户名单、订单推品项目数据四个页面。
3. 15 条用户样例与 14 条订单样例。
4. 全局筛选、指标计算、Trigger 分析、生命周期和商品类目识别逻辑。
5. 转化用户名单的 Excel 式字段筛选、逐格编辑和本地保存。
6. 页面初始化、导出与弹窗交互。

日常开发修改 `index.html`，不要直接编辑 `baseline/v1.9-baseline.html`。后者用于回溯和比对原始版本。

## 当前工作副本调整

- 转化用户名单不再展示“月份”字段；原始样例数据中的月份值仍保留，避免破坏历史数据。
- 国家、广告位、负责人、转化跟踪、第三方插件、是否流失、是否完成、流失监控系统按单值标签展示和编辑。
- 转化原因、流失原因按多值标签展示，点击标签区域可勾选、取消或新增标签。
- 同一字段下的不同标签值使用稳定的差异化颜色；负责人、国家、广告位等不再共用一种颜色。
- 标签右侧的小三角默认隐藏，仅在当前标签弹窗展开时显示。
- 单选和多选标签弹窗均支持搜索；输入不存在的内容时可以直接“添加选项”，并把新标签写入当前字段。
- 时间、标识和数值字段继续使用原有编辑方式，不混入标签体系。
- 全站使用黑色箭头配蓝色光晕的自定义鼠标指针。
- 转化用户名单横向滚动时冻结 `user_id`、用户注册邮箱、转化CAM、国家四列。
- 流失日期为空时保持空白，点击单元格后再显示日期编辑控件。
- 页面和表格控件统一使用微软雅黑。
- PL、US、AU、CA、UK 使用固定且互不重复的国家标签色，并在悬停提示中展示中文国家名。
- 用户注册邮箱和转化链接以可点击超链接展示，右侧悬停编辑按钮可继续修改原值。
- 自定义鼠标指针已缩小为 24×24 像素。
- 新增国家代码会自动获得新的标签颜色，颜色映射保存在浏览器 `tdfx_country_colors_v1` 中；支持 ISO 国家代码自动显示中文国家名。
- CAM ID 改为深灰色，避免与超链接蓝色混淆。
- 所有标签型字段为空时保持空白，点击空白单元格仍可添加标签。
- 转化用户名单采用接近 Power BI 的浅蓝色间隔行，提升横向浏览辨识度。
- “操作”字段改为单值标签：与国家、负责人等字段一样支持搜索、选择和新增选项。
- 转化用户名单按“转化日期”的年份自动生成独立页签；新增 2025、2027 等年份数据时会自动增加对应年份表。
- “流失待分析”不再在打开程序时自动弹出；转化用户名单右上角提供警铃入口和实时数量，点击后查看全部待分析记录。
- 待分析弹窗中的“查看”会关闭弹窗、自动切换年份和展开月份，滚动并高亮对应 CAM；目标受字段筛选隐藏时会自动清除筛选。
- 所有标签字段统一支持多选切换：点击标签立即选中并保存，再点同一标签即取消；可在一个单元格内同时保留多个标签。
- 每个年份页签内再按“转化日期”的月份分组，月份分隔行显示记录数并支持展开、折叠。

## 已确认的本地存储

- `tdfx_users_v14`：转化用户名单编辑缓存。
- `tdfx_orders_v13`：订单推品项目数据缓存。
- `tdfx_continuous_v1`：持续出单时长状态。

浏览器缓存中的旧数据会继续影响页面显示。调试样例数据时，如发现页面与源码不一致，应先检查对应的 `localStorage`。

## 后续开发原则

- 保持已经确认的数据口径不变。
- Trigger 只描述已转化 CAM 的结构和表现，不解释为严格因果效果或真实转化率。
- 一个 CAM 只能归属一个最终 Trigger 组合。
- 修改功能时同步更新技术文档与版本说明。
- 在业务稳定后，再逐步将数据、规则、渲染和交互从单文件拆分为独立模块。

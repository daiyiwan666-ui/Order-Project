## 启动与检查

需要 Node.js 18 或以上，不需要执行 npm install。

```powershell
npm run dev
```

浏览器打开 http://127.0.0.1:4173。PowerShell 如限制 npm 脚本，可使用 `npm.cmd run dev`。也可运行 VS Code 任务“启动 V2.0 本地预览”。

当前工作区该地址默认为云端模式；原本地演示地址为 http://127.0.0.1:4173/?mode=local。

```powershell
npm run check
npm test
# 可选：先 npm ci，再安装 Chromium，运行登录与人工保存的浏览器测试
npx playwright install chromium
npm run test:cloud-browser
```

check 检查样例、CAM 唯一性、字段及全部本地脚本语法；test 验证导入映射、异常判定、状态及持续出单规则、多种表格格式解析。表格组件已随项目提供，上传和 Excel 导出不再需要联网加载 CDN。

## 每日上传转化数据

以下上传预览和业务规则适用于本地及云端模式。云端采用分块上传与服务端再次校验，支持中断后继续/终止；详见云端说明。

1. 打开“转化用户名单”，点击右上角“上传文件”。
2. 选择文件，在预览中核对工作表、字段映射及新增/更新/异常数量。
3. 点击“导入正常记录并登记预警”。正常记录自动写入，异常记录保留原值。
4. 点击警铃进入异常预警中心。订单回退等可复核异常，点击“确认更新”并确认后才写入；无效数据需修正文件再上传。“查看”只定位 CAM，不批准更新。

支持 `.xls`、`.xlsx`、`.xlsm`、`.xlsb`、`.xlt`、`.xltx`、`.xltm`、`.csv`、`.tsv`、`.ods`，单文件不超过 32MB。可选择工作表；CSV/TSV 默认 UTF-8，乱码时可切换 GB18030/GBK。加密、损坏或缺少必需表头的文件会提示错误，不会清空原数据。

每日自动化以用户上传最新文件为触发，不包含定时从外部接口抓取。

## 映射与更新规则

- 转化CAM = 广告id。长 CAMid 和用户ID保持为文本，无法可靠识别的数值长编号会提示修正。
- 广告位 = 转化素材；转化链接 = 推荐供端URL。
- 国家 = 主营国家；商品标题 = 销端商品标题；用户注册邮箱 = 用户邮箱。
- 转化日期 = 广告转化时间；最近下单日期 = 最近下单时间。
- 转化下单量 = 下单总数；支付订单 = 完成支付总数。
- 第三方插件 = 第三方履约app名；是否流失、流失日期按同名字段同步。
- 标签分类提取负责人和转化原因。unmapped商品 归一为 Unmmapped商品；未通过DSers下单 归一为 未通过DSers下单行为。忽略中用户、新品、运营日期标记、推荐供端部分SKU缺货、推荐供端缺少SKU。
- 表头支持源字段名或程序标准字段名。同一目标同时出现两种列名会报错，不猜测多个源列的优先级。

新 CAM 新增；已有 CAM 的日更仅替换最近下单日期、转化下单量、支付订单、是否流失、流失日期，并联动转化跟踪、持续出单时长及最后编辑时间。订单是累计快照，不相加。

已有 CAM 的身份、转化日期、商品资料和原因等不随日更覆盖；转化备注、流失原因、流失备注、操作、备选推荐供端、是否完成由人工维护。重复上传无变化不更新最后编辑时间。

## 状态与持续出单时长

| 转化跟踪 | 条件 |
| --- | --- |
| 待下单 | 下单量为 0 且是否流失为 no |
| 下单中 | 下单量不为 0 且是否流失为 no |
| 已流失 | 是否流失为 yes，且不满足回流条件 |
| 流失又回 | 是否流失为 yes，且最近下单日期至少为流失次日 |

流失当日再次下单仍算已流失。状态为系统派生字段；是否流失使用单选是/否。日期按业务日历比较，系统编辑时间使用 Asia/Shanghai。

首次观察到下单时固定起点，之后最近下单时间更新不重置。首次导入及旧缓存迁移不能还原首次下单时，使用转化日期作为历史估算起点；待下单不计时。流失时以流失日期停止，回流时从观察到的回流下单时间恢复，保留旧区间并排除流失期间。多次历史流失/回流无法从一份累计快照完整还原。

时长按各有效区间的总时长折算完整天数，导出与页面使用同一计算结果。历史 V1.9 支付门槛及最近下单日起点不再使用。

## 异常预警中心

右上角原“流失待分析”警铃扩展为统一入口。单一类型显示对应文案，多类型显示“异常预警中心”。角标按待处理 CAM 去重，缺少 CAM 的异常按导入记录计数。

检测订单回退、无效/缺失订单数、空/冲突CAM、CAM用户归属冲突、下单日期回退、日期逻辑异常、流失日期缺失、关键更新信息缺失、支付量大于下单量及互斥原因标签。

- 可复核的订单回退、下单时间回退、支付量大于下单量暂缓整行日更，人工确认后写入同一快照的日更字段。
- 无效值、缺失信息、身份冲突、矛盾日期等不能直接确认，需修正文件。
- 可“忽略本次”，不修改数据；重复导入同一异常不重复创建待处理条目。
- 新的正常更新可替代旧的待确认候选；若预警产生后该行订单等已变化，旧确认会拒绝，需重新上传。
- 查看沿用切换年份、展开月份、清除遮挡筛选、滚动高亮的逻辑。
- 预警、用户和计时状态一起保存，刷新不会丢失。支付订单单次增加40的既有提示及单元格标识仍保留，增长不直接视为错误。

本地存储：

- `tdfx_workspace_v20`：用户名单、持续出单区间、预警事件的统一快照。新增行数不再受15条限制。
- `tdfx_users_v14`：仅用于迁移旧名单；迁移后不再向旧键写入。
- `tdfx_continuous_v1`：旧计时缓存保持原样，因口径变化不作为新计时结果使用。
- `tdfx_orders_v13`：订单推品页面缓存。
- `tdfx_country_colors_v1`：国家标签颜色。

导入先计算，再保存统一快照，保存失败不改内存数据。其他窗口已修改同一快照时会提示刷新，避免覆盖。数据仍存于本浏览器、当前页面来源中，需自行导出备份；不自动同步到其他电脑、浏览器或GitHub。

# V2.1.0-beta.2 云端导入与预警

日期：2026-10-23。前提：第一步真实网页登录、管理员认领、人工备注保存与刷新重读已验收通过。

## 本轮范围

在现有“转化用户名单”开放云端上传、每日累计订单替换、共享预警确认/忽略和出单区间联动。原 V2.0 本地模式保留；不自动迁入浏览器缓存或原始演示数据。订单推品页面仍只读，实时同步、服务端筛选分页汇总及备份恢复另行完成。

## 导入流程与失败恢复

1. 浏览器读取Excel/CSV等支持格式，计算原文件SHA-256，展示原有映射和预览。
2. 以一次导入的request_id创建云端批次。所有源行连同物理行号、解析问题和预览版本一起上传，最多每块200行，按UTF-8字节进一步拆分。
3. 全部分块收齐后，服务端封存文件并统一识别整份文件中的重复CAM。相同业务数据合并；冲突重复整组不入表，包括跨分块的重复。
4. 每次处理一个分块，在同一数据库事务中校验和写入正常行、登记异常、维护出单区间和审计，并更新批次计数。每一块提交后可以独立恢复；整份文件不保证一次事务回滚。
5. 处理完成后清除私有暂存表中的整份文件payload，仅保留重试摘要和处理记录。异常候选留在共享预警中。

相同request_id重试不会重复计数和写入；分块内容发生改变时拒绝复用该请求。即使保存成功后的网络响应丢失，重试也能查询原批次结果。

当前页面可直接重试同一导入。刷新后，“未完成导入”可以继续处理已完整上传的文件。若分块未收齐，可终止该批次后重新选择文件。终止会清理暂存内容，但不撤销先前已提交的数据。未完成且尚未终止的上传暂存仍占数据库空间，可从该入口终止清理。

文件上限仍为32MB；单次最多10000个非空源行、最多100个分块，过大文件需拆分。浏览器单块保守限制为900KB，数据库块请求限制为1MiB。上传源文件在浏览器解析，整份二进制文件不存Supabase Storage；私有暂存只保存规范化行数据。

## 服务端规则

- CAM和业务用户ID必须是文本；无效/丢失精度编号登记不可确认的预警。
- 新CAM创建；已存在的CAM只替换最近下单日期、转化下单量、支付订单、是否流失和流失日期。订单为累计快照，不相加。
- 已有身份、转化时间、标题、标签和人工复盘字段保留。转化备注、流失原因、流失备注、操作、备选推荐供端、是否完成均不从文件覆盖，即使文件含这些列也不作为导入赋值。
- 新记录从源标签提取负责人和转化原因；同义标签归一，运营、新品和不纳入字段的标签忽略。数据库再次校验标签和互斥组。
- 源文件中不参与可见字段映射的列作为隐藏source_extras保留在新CAM，已有CAM不随日更覆盖。不会猜测源文件没有提供的套餐等信息。源文件存在的“首次下单时间”仍按隐藏字段保留，本轮沿用此前确认的历史起点口径，不自动改变计时规则。
- 每行核对预览时的row_version；新增时若CAM已被其他操作创建，或旧CAM在预览后被修改/删除，则暂缓并提示重新上传。
- 订单缺失/负数/小数、不安全数值、身份冲突、矛盾日期、缺失关键时间、缺失流失日期、互斥标签等为硬错误，不可直接确认。
- 订单回退、最近下单时间回退、支付订单大于下单量等可复核异常暂缓整行更新，保留历史值。
- 相同异常指纹不重复登记，忽略后重传完全相同的候选不会重新弹出。新的正常快照会替代旧待确认候选，CAM无变化时不因此递增其编辑时间或版本。

## 预警确认与并发

预警中心读取共享pending记录，显示文件名、源行、前后值和问题。查看只定位；查看者可查看，不显示确认与忽略按钮，服务端也拒绝其处理请求。

确认同时校验预警行版本和CAM版本，并重新执行业务校验。在同一事务中保存累计值、派生状态、出单区间、审计及预警处理状态。另一位成员已处理或CAM已有更新时拒绝旧确认；需刷新核对，CAM变化的候选应重新上传文件。忽略不修改CAM，只记录预警处理结果。

## 状态与计时

状态沿用四种：未流失且0单为待下单；未流失且非0单为下单中；流失为已流失；流失日期次日或之后有最近下单才算流失又回。同日下单仍算已流失，按Asia/Shanghai日历日期比较。

历史首次导入已下单的CAM以转化日期估算起点；已入表待下单CAM首次观察到订单时，以当次最近下单时间固定起点。后续最近下单时间变化不重置活动起点；流失按流失日期停止；回流从首次观察到的回流订单时间恢复，累计旧区间并排除流失间隔。支付订单为0不阻止计时。展示时计算总有效时长，不持续写库。

## 数据库与权限

公开RPC为 `op_import_file` 和 `op_resolve_alert`，保持SECURITY INVOKER包装。私有实现逐次检查登录和有效编辑成员权限；批次上传/恢复只允许原上传者操作。所有业务表继续启用RLS，浏览器无直接写表权限。

新增 `order_project_private.import_uploads` 与 `import_chunks` 作为暂存与收据，启用RLS并明确关闭直接客户端访问。导入/预警处理串行协调，单块事务尽量短；人工单行修改通过行锁和版本保护衔接。

迁移历史包括 `cloud_imports_and_alerts`、两次SQL命名修正、导入中断恢复及参数校验加固；仓库文件版本与实际远端历史对齐，不改写已应用记录。

## 网页验收文件（2026-10-23更新）

用户希望按四个独立文件分四步上传，避免将多工作表文件误认为会一次全部入库。已拆分为以下材料，推荐 [ZIP打包下载](../assets/examples/qa-cloud-import-4-files.zip)，解压后按01至04顺序上传。四个文件使用同一CAM `QA-UPLOAD-20261023-B1`，均为合成数据，每个文件仅一张工作表、一条数据。

| 文件 | 预期 |
| --- | --- |
| [01 新增5单](../assets/examples/qa-01-new-5.xlsx) | 新增CAM，下单5、支付3；填写人工转化备注并刷新核对 |
| [02 正常更新6单](../assets/examples/qa-02-update-6.xlsx) | 更新为下单6、支付4；此前人工备注保留 |
| [03 异常回退2单](../assets/examples/qa-03-regression-2.xlsx) | 暂缓并保留6/4；确认预警后才改为2/1 |
| [04 无效订单不可确认](../assets/examples/qa-04-invalid-negative.xlsx) | 负订单量阻止写入，预警不提供确认按钮，保持2/1 |

原 [四工作表合集](../assets/examples/qa-cloud-import.xlsx) 保留作补充。已核对 `buildImportPreview()` 从 `importWorkbook.Sheets[userImportSheet.value]` 提取数据；云端导入只发送当前解析的行和所选工作表名称。整份文件在浏览器读取并计算摘要，不会自动把所有工作表合并写入。发现多个候选工作表时默认选择首个带有效表头的工作表，其他工作表需手动切换后另行应用。

验收文件验证：四个文件分别重新读取，确认每个仅一张工作表，内容与原合集对应表一致；使用当前导入规则按顺序验证结果为新增、更新、待复核、阻止写入。第三步的更新仅在模拟确认后用于第四步校验，未向真实数据库导入测试数据。这是测试材料验证，不替代用户真实网页验收。

每步完成后刷新核对，先保留测试CAM以便数据库复核，再按软删除语义清理。如果已测试到后续步骤，不盲目重传01：较低累计值可能触发正常的回退预警，应先核对当前进度再继续。
